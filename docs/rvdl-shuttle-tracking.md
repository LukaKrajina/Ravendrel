# 「穿梭」与「追踪」—— `@layer` 的两个新机制

> 本手册定义 Ravendrel `@layer` 标签的两个扩展机制：**穿梭（shuttle）** 与 **追踪（tracking）**。
> 二者不是两个独立特性，而是**一对互补的量子数据流原语**——
> 穿梭提供「广播式非消耗」的关联层渗透，追踪提供「软克隆式经典影子」的非破坏读出。
> 核心依赖关系：**穿梭的量子相干路径在物理上无法独立实现，必须由追踪供给经典影子缓冲区。**

## 1. 为什么需要这两个机制

现有 `@layer` 的五种拓扑边（`stack` / `parallel` / `projection` / `inversion` / `crossing`）
描述的是**块与块之间的几何关系**，而调用传播（`callGraph` 的 `Δt`）描述的是**单链式顺序数据流**。
后者有两个结构性缺陷：

| 缺陷 | 表现 |
| --- | --- |
| **深度 O(N)** | 叠加链上第 1 层的数据到达第 N 层需要 N−1 次串行跳转 |
| **消耗式** | 数据沿链传递后，源端的量子态已被门操作改变，无法复用于其它关联层 |

这正是经典「前向传播 + 反向传播」的固有局限。二者要突破的正是这两点：
**穿梭**把 O(N) 深度压到 O(log N)（蝶式）、O(1)（Grover 扩散 / c001 蝶点），
并支持**全体并行**渗透；**追踪**让数据在渗透过程中保持**非消耗**（软克隆），
因此可以同时喂给多个关联层。

## 2. 研究依据

### 2.1 穿梭

| 来源 | 核心结论 | 启示 |
| --- | --- | --- |
| MPI 集合通信（Thakur/Sverdrup, *mlsysbook* 集合通信章） | 递归倍增/蝶式 AllReduce **O(log N)** 步达成全连接；环式需 **O(N)** 步。1024 节点：环 2046 步 vs 树/蝶 20 步 | 「更高效」的严格依据：深度降 `N / log₂N` |
| 蝶式网络（recursive doubling / butterfly） | N 节点编为 k=log₂N 位超立方体；每阶段翻转一位 → 每阶段一个**全体并行置换** | **`coord` 本就是整数向量 = 现成的超立方体地址**。一轮穿梭 = 翻转 coord 的一位 |
| 蝶式的带宽项与环式相同（集合通信实测） | 每跳带宽一致 → 大消息下环式的 O(N) 门数优势可压过蝶式的 O(N) 深度劣势 | 「逐位翻转」搬运的是**全量数据**；c001 蝶点（§3.7，本项目自有扩展）改为上传**主要特征摘要**，把深度钉死在 1 轮 |
| 振幅放大（Brassard-Høyer-Tapp 1997；Grover 扩散算子） | 扩散 `S_ψ = I − 2\|ψ⟩⟨ψ\|`，配合 `H^⊗n` **一步**把振幅全局混合到全体基底态 | 量子原生的 **O(1) 深度全局穿梭**——经典前向/后向传播无法达到 |
| 稠密 / 全尺度跳连（U-Net 2015；DenseNet 2017；UNet3+ 2020） | UNet3+ 第 j 层节点接收 j+1 个编码器尺度的输入；DenseNet 每层与所有后续层直连 | 「在共享**之前和之后**渗透」的经典对应：前向（更深）+ 后向（更浅）两个传播锥的**并集** |
| 全息编码（AdS/CFT holographic codes） | 编码在体（bulk）的信息可从**边界两侧精确恢复**（exact two-sided recovery），保持平坦纠缠谱 | 「之前和之后**同时**可及」的物理合法性：穿梭是**双侧恢复算子**，不是单向链 |
| 完美态传递（Christandl et al., *Nature* 2004） | 工程化耦合可在**固定时间**内完美传递任意量子态；SWAP 链「每跳都耗时、期间退相干」 | 非链式穿梭的效率优势有物理意义（省的不只是门数，是**退相干时间**） |
| 项目自有 `geodesic_distance(a,b)`（Fubini-Study） | 射影希尔伯特空间上的测地距离，经 SWAP-test 重叠计算 | 形式化「哪怕关联度极小也有效」：`w = exp(−d/λ)` 是**处处严格为正、无阈值**的核 |

### 2.2 追踪

| 来源 | 核心结论 | 启示 |
| --- | --- | --- |
| 不可克隆定理 | 不能克隆**任意未知**量子态 | 必须区分三种情形，否则设计会过度承诺 |
| Peierls 定理 / QND 测量 | Pauli 族可观测量（X/Y/Z）在其本征基下测量**不扰动态**，可任意次重复读取且精确 | **L0 无损级**：软克隆精确、零扰动、可无限次 |
| 经典阴影（Huang-Kueng-Preskill, *Nature Physics* 16, 1050, 2020） | 随机 Pauli 测量 → 单比特快照 → `ρ̂ = 3U†\|b̂⟩⟨b̂\|U − I`；k-局域算符阴影范数 `‖O‖²_shadow = 3^k`；浅阴影（You et al., arXiv:2407.03380）进一步优化 | **L1 统计级**：任意可观测量用 N 次采样得到**经典**副本，N↑ 则保真度→1。副本是经典的 → 不触碰不可克隆定理 |
| 逆计算 / 辅助比特复用（Bennett 1973；SQUARE, ISCA 2020） | 把 ancilla 中的结果反向运行电路复位（uncomputing）后即可**复用该 ancilla** | 三段式协议的第三段：`Extract → Copy → Restore`，代价 2× 计算但两份都在 |
| 子系统码（Subsystem codes / 纠错 zoo） | 规范量子比特被测量、逻辑量子比特存活 | 与 RVDL 的量子线性类型 QLT（no-cloning + 恰好消费一次）呼应：影子槽必须是**经典标量类型**，绝非 `QObject` |

## 3. 穿梭（shuttle）

### 3.1 定义

设层集合 𝕃，其关联图 𝒢 的边由既有五种拓扑边构成。
层 `a` 声明 `shuttle=(c₀,…,c_{m−1})` 后，编译器求出

```
𝕊(a) = { b ∈ 𝕃 : coord(b) = c  (c ∈ 声明的目标)  且  𝒢 上 a ↔ b 存在关联边 }
```

然后以关联度为权重，把 `a` 的数据在**共享点的前后**双向渗透进 𝕊(a)。

关联度核（Fubini-Study 测地尺度上的指数核）：

```
w(a, b) = exp( − d(coord_a, coord_b) / λ )
```

- **编译期**：用 L1 编码距离 `d(coord_a, coord_b) = Σᵢ |aᵢ − bᵢ|`（与既有 `logical_qubit_layout`
  所用的码距一致，廉价且可静态计算）。
- **运行期**：若两端持有量子态，可用项目自有的 `geodesic_distance(a,b)`（SWAP-test 重叠）
  细化关联度。

> **「哪怕关联度极小也有效」的严格保证**
> 指数核**在编译期与运行期都不设截断阈值**：`w > 0` 恒成立（除非 `λ ≤ 0`，报 `E-SHU003`）。
> 这与注意力 softmax 根本不同——softmax 会把小权重归零，穿梭不会。
> 唯一的例外是运行期 `w` 低于机器精度时按浮点下溢自然消失，这是数值效应而非语义截断。
>
> **下溢墙的确切位置**：`exp(−x)` 在 `x ≈ 745.13` 处取到整零
> （实测二分夹逼，见 `runtime/benchmarks/shuttle_plan_benchmark.cpp`）。
> 注意不要把它与 `ln(DBL_MAX) ≈ 709.78` 混为一谈 —— 后者是**正规数**下界，
> 越过它只是进入次正规区，`w ≈ 5.6e-309` 仍然非零；两者相差 35，
> 混用会让「下溢」的判断落在错误的距离上。
>
> 越过墙之后 `logWeight = −d/λ` 仍**严格可分辨**（`−800 > −801 > −802`），
> 而 `weight` 已全部为 0 —— 这正是「路由一律用 `logWeight`」这条纪律的全部意义，
> 也是下溢对端**仍被调度**的原因。

### 3.2 相位（共享点前后）

`shuttle_phase` 控制渗透轮次相对**目标层** time-slot 的执行时机：

| 值 | 含义 | 执行点 | 效果 |
| --- | --- | --- | --- |
| `0` | 仅共享**前** | 目标层**入口** | 载荷写入目标影子 → 目标把该关联当作**输入**看到 |
| `1` | 仅共享**后** | 目标层**出口** | 目标影子回灌进载荷的**返回腿** |
| `2` | **前后都渗透**（默认） | 两者都做 | 两个传播锥的**并集**——每个关联层同时是源与汇 |

`phase=2` 是双侧恢复算子（对应全息编码的两侧恢复）：所有关联层既被上游渗透，也向下游渗透，
覆盖面严格大于 `0` 与 `1`。

#### 为什么需要「渗透载荷」这一中间通道

影子槽的生命周期 = 块自身的 `[time, time+cost)` 窗口（见 §4.4），而源与目标的窗口
**通常不相交**（如 `sense@t0` → `relay@t1`）。若在目标的边界直接读源的影子，
窗口早已关闭 —— 机制要么失效，要么必须让影子越界存活，而后者违反 §4.4 的
「不构成持久克隆」。

因此引入**渗透载荷**：源在自己窗口的末尾把影子快照进载荷，载荷跨窗口传递到目标的
边界再落地。载荷是**经典关联标量**（不是量子态的副本），因此不触碰不可克隆定理；
它随链接在运行期存续，而不是随块栈帧消亡。

这与 §4.4 并不冲突：**被克隆的从来不是量子态**，而是「影子」（经典标量），
以及影子之上的关联度加权值。

### 3.3 轮次规划

`shuttle_rounds=0`（默认）表示 auto，轮次由超立方体宽度决定：

```
k = ⌈log₂(span)⌉   其中 span = ∏ᵢ (coord_max[i] − min(0, coord_min[i]) + 1)
```

> 各维取**格点真实跨度**。coord 是格点**地址**而非计数，可为负；
> 若写成 `coord_max[i] + 1`，全负地址的拓扑会得到 `span = 1` → `k = 0`，
> 穿梭静默地一轮都不做。当全部 coord ≥ 0 且最小值为 0 时，
> 本式退化为 `coord_max[i] + 1`（既有行为不变）。

蝶式规划下，第 `j` 轮（`j = 0..k−1`）对 `coord` 的第 `j` 位做翻转置换，
一轮即让全体关联层同时收到彼此的一份（按 `w` 加权）。

### 3.4 五种策略的诚实代价表

深度列同时给出**解析式**（`n` = 关联层数，`span` = 格点跨度 `∏ᵢ(coord_max[i] − min(0, coord_min[i]) + 1)`）。
解析式不是示意 —— 它就是 `shuttle_rounds=0`（auto）时实际执行的轮次数，
由编译期 `strategyDepth()` 与运行期 `depth_of()` **同式**给出。

| `shuttle_strategy` | 名称 | 深度（解析式） | 总门数 | 语义 | 附加资源 |
| --- | --- | --- | --- | --- | --- |
| （基线） | 现有 stack 链 | **O(N)** = `n` | O(N) | 逐跳串行 | 无 |
| `0` | **蝶式**（默认） | **O(log span)** = `max(1, ⌈log₂ span⌉)` | O(N log span) | 全体并行置换 | 无 |
| `1` | 环式 | O(N) = `n` | O(N) | 最近邻 | 无 |
| `2` | 树式 | O(log N) = `⌈log₂(n+1)⌉` | O(N) | 树汇聚/散播 | 无 |
| `3` | **Grover 扩散** | **O(1)** = `1` | O(1) + 辅助寄存器 | 振幅全局混合 | 2ⁿ 工作寄存器 |
| `4` | **c001 蝶点** | **O(1)** = `1` | O(N)（一轮） | 主要特征压缩成点再辐射 | **无** |

> 该权衡真实存在：研究已证实蝶式的**带宽项与环式相同**（每跳带宽一致），
> 故大消息 / 层级集群下环式的 O(N) 门数优势会压过它的 O(N) 深度劣势，可能反超蝶式。
> 因此 `shuttle_strategy` 必须是可调旋钮而非写死。
>
> `strategy=3` 是**经典基前向传播无法达到**的深度（O(1) 覆盖全体），代价是 2ⁿ 工作寄存器；
> 缺寄存器时报 `W-TRK001`，**重新规划**为策略 `0`（而非只改标签 —— 见 §3.4.2）。
> `strategy=4`（c001 蝶点）同为 O(1) 深度但**资源模型相反**：零附加资源，
> 代价是全体关联层只上传**主要特征摘要**而非全量数据（见 §3.7）。

#### 3.4.1 轮次必须**按策略**解析（不存在普适深度排序）

环式深度跟 `n` 走、蝶式深度跟 `span` 走 —— 两者之间**没有**固定的大小关系：

| 拓扑 | 蝶式 | 环式 | 谁更浅 |
| --- | --- | --- | --- |
| 1024 个对端挤在 `coord ∈ {0,1}`（`span=2`） | 1 | 1024 | 蝶式 |
| 2 个对端相距 1000（`span=1001`） | 10 | 2 | 环式 |

因此轮次不能统一套用蝶式公式 `⌈log₂ span⌉`。这曾是**实际存在的缺陷**：
轮次既是执行量、又是 `E-SHU007` 的 deadline 诊断量，统一套一个式子会让
环式 / 树式的代价被**系统性低估**（`n` 稍大就差一个数量级），
而运行期的展开又各按各的算 —— 两端各自「自洽」，接起来是错的，且不会有任何报错。

订正后的分工：

| 量 | 谁定 | 说明 |
| --- | --- | --- |
| `shuttle_rounds > 0` | **用户** | 权威值，原样执行（任一策略） |
| `shuttle_rounds = 0` 时的轮次 | **所选策略的解析式** | 即上表「深度（解析式）」列 |
| `E-SHU007` 的代价 | 同上 | 与实际执行的轮次数**逐点相等** |

`span ≤ 1` 的退化拓扑（全部块同 coord）解析为 `max(1, ·)` = 1 轮：
声明了对端就意味着至少一次交换，解析为 0 轮会让整个机制**静默失效**。

#### 3.4.2 Grover → 蝶式的降级必须**重规划**

`W-TRK001` 触发时不能只把策略标签改成 `0`：Grover 的轮次是 `1`，
而蝶式需要 `⌈log₂ span⌉` 轮。只改标签会留下「标签写着蝶式、计划里只有 1 轮」
的静默不一致 —— 1 轮蝶式只翻 `coord` 的第 0 位，绝大多数格点收不到渗透，
恰是本机制最要命的失败模式。故降级路径**重新规划**并记录实际轮次数。

### 3.5 auto 策略选择启发式（默认）

`shuttle_strategy=-1`（默认）时由运行时启发式决定：

```
若 关联层数 N ≤ 2                     → 0（蝶式；蝶式在极小规模无劣势）
否则若 存在量子载荷 且 ancilla 充足    → 3（Grover 扩散，O(1) 深度）
否则若 载荷为长消息（大向量/稠密态）   → 1（环式，带宽项优）
否则若 格点跨度 span ≥ 16 且 N ≥ 4    → 4（c001 蝶点，深度与 span 无关）
否则                                    → 0（蝶式）
```

选择结果会写入运行期诊断输出（含选了哪个策略、依据为何），**不静默决定**。
第四条分支的理由：蝶式深度跟 `span` 走，远端对端越多越深；而 c001 蝶点恒 1 轮
且零附加资源。span 尚小（< 16）或对端太少（< 4）时蝶点无收益，仍回落蝶式。

### 3.6 载荷语义

| 载荷 | 混合算子 |
| --- | --- |
| 经典标量 / 影子槽位 | 按 `w` **加权加法混合**（不截断） |
| 量子态（`QObject`） | 受控 SWAP 梯：把源态**移动**到对端（保不可克隆）；若 `strategy=3` 则叠加 `H^⊗n·S₀·H^⊗n` 扩散算子 |

量子路径必须**读取**对端而不消耗它——这在量子条件下无法独立做到，必须由追踪供给经典影子。
见 [§5](#5-两机制的耦合)。

### 3.7 c001 蝶点：压缩成点再辐射，DNA 链多层架构

蝶式让数据在 `⌈log₂span⌉` 轮里逐位翻转跳向对端 —— 相距 `d` 的对端要 `log₂d` 轮才收到，
且每轮都是全量置换搬运。**c001 式**把「跳过去」改为「**压缩成一个点再辐射**」：

```
            汇聚（capture）                     辐射（radiate）
   各关联层主要特征摘要 ──────────▶  ┌──────────┐  ──────────▶ 全体关联层
   （关联度加权的经典标量）          │  蝶 点   │   phase=0 入口 / phase=1 出口 /
                                     │ digest   │   phase=2 双侧（默认）
                                     └──────────┘
```

- **蝶点**（butterfly point）是该穿梭群的显式特征点：全体关联层各自上传主要特征摘要
  （即渗透载荷，见 §3.2），摘要在此点上有序集合，再按相位语义向全体辐射。
- **深度恒 1 轮**：汇聚与辐射在同一轮的双侧相位内完成，与 `span` / 对端数全部无关 ——
  远端对端不再随 `log₂d` 加深。这是相对蝶式的性能差，也是与 Grover 的关键区别：
  两者同为 O(1) 深度，Grover 需 2ⁿ 工作寄存器（不足则降级），蝶点**零附加资源**。
- **蝶点不改变加权语义**：辐射到每个对端的值仍是「蝶点摘要 × `w = exp(−d/λ)`」，
  与其它策略共用同一套无截断核（§3.1）。c001 改的是**深度与覆盖**，不是权重。

**DNA 链多层架构**（"如同 DNA 链"的落地形态）：

| DNA 概念 | c001 对应物 |
| --- | --- |
| 双螺旋主链（backbone） | **蝶点链**：多个穿梭群各有一个蝶点，蝶点之间互相 `shuttle`（经既有五类拓扑边互联） |
| 碱基对（base pair） | **横档**：每个关联层通过其所属群的蝶点，与全体关联层一一配对 |
| 双链互补 | `phase=2` 时每个蝶点同时是上游的**汇**与下游的**源**（双侧恢复算子，§3.2） |

多层性来自组合而非新键：一个块可以同时是 A 群的蝶点、B 群的叶子、C 群的链节点 ——
群的边界由 `shuttle=(c,…)` 声明自然形成，无需额外语法。运行期为每个蝶点打印
`c001 蝶点 digest` 诊断行（含摘要内容与对端数），**决策与内容可见，不静默**；
`ShuttleRuntimeStats::c001_points` 计数显式物化的蝶点数。

完整可运行示例见 `examples/c001_dna_chain.rvdl`（双蝶点链 + 四叶子层 + 自检）。

## 4. 追踪（tracking）

### 4.1 四段式协议

严格对应「暂时转换经典值并复制它们，将之前的值恢复到量子态」：

```
┌─ 作用域建立（进入块的 [time, time+cost) 功能周期）
│
├─ ① EXTRACT   施加抽取电路（基旋转 → 测量 / QND 读出 / ancilla 计算）
│                 量子态被暂时投影 / 降维 → 经典比特 b ∈ {0,1}^m
│
├─ ② COPY      b 写入 track_slots 个经典影子槽
│                 经典数据 → 可任意复制，不触碰不可克隆定理
│                 槽位是块的局部变量
│
├─ ③ RESTORE   反向运行 ① 的电路（uncompute ancilla / 按 b 重制备）
│                 原始量子态回到线上；以 qstate_fidelity 校验 ≥ 阈值
│
└─ 作用域销毁（周期结束，影子槽随帧释放）
```

### 4.2 保真阶梯（三级）

**单次软克隆在物理上不可能。** 测 `Z` 基得 `b` 后，测量后态为 `|b⟩`，逆推只能得回 `|0⟩`——
相位信息已不可恢复。因此追踪采用三级阶梯，**不做统一精确承诺**：

| 级 | `track_mode` | 适用可观测量 | 保真度 | 代价 | 依据 |
| --- | --- | --- | --- | --- | --- |
| **L0** | `1`（`qnd`） | Pauli 族（`expect_z` / `expect_x` / `expect_y` / `measure_z` …） | **= 1 精确** | O(1) | Peierls 定理 |
| **L1** | `2`（`shadow`） | 任意可观测量 | →1 按 O(3^(k/2)/ε) 采样 | O(N 采样) | 经典阴影 |
| **L2** | `3`（`relabel`） | 已是经典值（已坍缩的 `int32` 等） | = 1 精确 | O(1) 自由 | 经典可复制 |

`track_mode=0`（默认）`auto` 按可观测量所属族自动选级：

- Pauli 族标识符 → L0
- 经典类型标识符 → L2
- 其余 → L1

**非零 `track_mode` 强制覆盖 auto**（不是建议而是覆盖）：

| `track_mode` | 下发级别 | 备注 |
| --- | --- | --- |
| `1`（`qnd`） | L0 | 对非 Pauli 族报 `E-TRK003`（不存在非破坏读出电路） |
| `2`（`shadow`） | L1 | 即使观测量本是 Pauli 族也强制降为 L1 |
| `3`（`relabel`） | L2 | 即使观测量本是统计量也强制升为 L2 |

> 强制**必须**真的改变级别，否则 `track_mode` 就是一个哑参数。
> 这一点由两侧的测试共同钉住：`server/src/tracking.test.ts`（编译期下发）
> 与 `runtime/tests/shuttle_topology_parity.cpp` §4（运行期规划）。
> 二者曾漂移过：编译期只把 `mode` 写进线格式却仍下发 auto 级别，
> 而运行期按 `mode` 强制 —— 两端各自「自洽」，接起来却是错的。

### 4.3 类型约束（保 QLT 不变量）

影子槽的类型是**经典标量**（`float` / `int32` / `double`），**绝不是 `QObject`**。

若影子槽被赋予 `QObject` 类型，将直接触发 `borrow.ts` 的：

- `E-Q001`（违反 no-cloning）
- `E-Q002`（线性值泄漏）

这与子系统码「规范量子比特被测量、逻辑量子比特存活」是同一结构：
**被测量的是影子，不是原态**。运行时对此有断言保护。

### 4.4 作用域

影子槽是块级局部变量，生命周期 = `@layer` 的 `[time, time+cost]` 功能周期。
周期外不可见 → **不构成持久克隆**，也无需全局 GC。

## 5. 两机制的耦合

```
                 ┌──────────────┐
                 │  @layer(     │
                 │    track=... │  ← 产出经典影子槽（经典类型，L0/L1/L2）
                 │  )           │
                 └──────┬───────┘
                        │ 经典影子槽（缓冲区）
                        ▼
                 ┌──────────────┐
                 │  @layer(     │
                 │   shuttle=.. │  ← 用影子槽做加权混合 / 受控 SWAP 读出
                 │  )           │
                 └──────────────┘
```

**为什么这是必需的而非可选的：**

1. 穿梭的量子载荷路径要「读取对端态而不消耗它」。量子力学禁止克隆，读取（测量）
   又会破坏态。唯一合法出路是 **QND 读出（L0）** 或 **经典阴影（L1）**——即追踪。
2. 反过来，追踪的 `RESTORE` 校验（`qstate_fidelity`）在存在穿梭对端时才有对照意义。
3. 二者合起来把「单链式消耗传播」改造为「广播式非消耗传播」，这正是相对
   前向/后向传播的质变所在。

**退化路径**：若声明了 `shuttle` 却未声明 `track`，穿梭的量子路径不可用 →
运行时退化为经典影子混合（若对端无任何影子则无法渗透）并报 `W-SHU001` 诚实告警，
**不静默伪造成功**。

## 6. 语法

两个机制作为 `@layer` 的**新键**，与既有键共存：

```rvdl
// ── 穿梭：向 coord=(1,0) 的关联层双向渗透 ──
@layer(time=1, thread=0, coord=(0,0),
       shuttle=(1,0),
       shuttle_lambda=0.5,
       shuttle_phase=2,          // 前后都渗透（默认）
       shuttle_strategy=-1)      // auto：运行时启发式选择
int32 propagate(QObject q) { return qstate_fidelity(q, q); }

// ── 追踪：软克隆 3 个可观测量，各留 2 份经典影子 ──
@layer(time=0, thread=0, coord=(0,0),
       track=(expect_z, measure_x, entropy),
       track_slots=2)
QObject sense(QObject q) { return qexpect_z(q, 0); }

// ── 组合：追踪提供影子槽，穿梭用它向对端混合 ──
@layer(time=0, thread=0, coord=(0,0),
       track=(expect_z,), track_slots=2,
       shuttle=(1,0), shuttle_lambda=1.0)
QObject relay(QObject q) { return q; }
```

### 键一览

| 键 | 类型 | 默认 | 含义 |
| --- | --- | --- | --- |
| `shuttle` | 数值列表（每项一个 coord） | 无 | 目标 coord；可多个 → 多个穿梭群 |
| `shuttle_lambda` | 标量 `> 0` | `1.0` | 关联度衰减长度（L1 距离单位） |
| `shuttle_phase` | 标量 `∈ {0,1,2}` | `2` | `0` 前 / `1` 后 / `2` 前后 |
| `shuttle_rounds` | 标量 `≥ 0` | `0` | `0`=auto（`⌈log₂span⌉`）或显式轮数 |
| `shuttle_strategy` | 标量 `∈ {-1,0,1,2,3,4}` | `-1` | `-1` auto / `0` 蝶式 / `1` 环式 / `2` 树式 / `3` Grover / `4` c001 蝶点 |
| `track` | 标识符列表 | 无 | 要追踪的可观测量 |
| `track_mode` | 标量 `∈ {0,1,2,3}` | `0` | `0` auto / `1` qnd / `2` shadow / `3` relabel |
| `track_slots` | 标量 `≥ 1` | `1` | 经典影子槽位数（复制份数） |

**向后兼容硬约束**：所有新键**可选且默认惰性**。
`@layer(time=0, thread=0, coord=(0))` 的既有语义与诊断结果**完全不变**。

## 7. 不变量与诊断

### 7.1 穿梭诊断

| 码 | 条件 |
| --- | --- |
| `E-SHU001` | `shuttle=(c…)` 目标 coord 无任何块匹配 |
| `E-SHU002` | 目标块存在但与本块**无关联边**（违反「前提…有关联」） |
| `E-SHU003` | `shuttle_lambda ≤ 0`（指数核必须严格正） |
| `E-SHU004` | `shuttle_phase ∉ {0,1,2}` |
| `E-SHU005` | `shuttle_strategy ∉ {-1,0,1,2,3,4}` |
| `E-SHU006` | `shuttle_rounds < 0` |
| `E-SHU007` | 规划轮次使执行超出 `deadline`（与 `E-TOP006` 联动） |
| `E-SHU008` | 穿梭对端与本块同 coord + 同 time（否则会撞 `E-TOP003`） |
| `W-SHU001` | 声明了 `shuttle` 但本块无 `@track` → 量子相干路径无经典影子供给，退化为经典影子混合 |

> `W-SHU001` 是**编译期**判定（「声明了 `shuttle` 却无 `track`」是静态可判的），
> 因此不必等到运行才告知。运行期仍会独立重复判定一次（`ShuttleRuntime::plan_all`），
> 以防调用方绕过编译器直接喂调度表 —— 两条路径都**不静默**。
>
> `W-SHU001` 走 **warning 通道**（`SemanticAnalyzer.warnings`）：编辑器显示为 Warning、
> `rvdl run` / `rvdl compile` 照常执行并在控制台打印，**不阻断** —— 它宣告的是
> 一条文档化的降级路径（退化为经典影子混合），不是必须修的错误。
> 若把它混进 error 通道，`errors.length > 0` 的中止检查会把程序毙掉，
> 文档承诺的「退化」永远走不到，告警本身反而成了阻塞。

### 7.2 追踪诊断

| 码 | 条件 |
| --- | --- |
| `E-TRK001` | `track=(...)` 为空，或 `track_slots < 1` |
| `E-TRK002` | 追踪源在该块作用域内**不可解析**：声明了 `track` 但块内没有任何量子源（无 `Qubit`/`QObject` 参数、无 `new QuantumRegister/DiracState/BellState`、无 `alloc()`、无返回量子态的内建/用户函数调用）—— 影子槽将永远填不满，故编译期拒绝而非静默登记 |
| `E-TRK003` | 可观测量标识符不在已知表内 |
| `E-TRK004` | `track_mode ∉ {0,1,2,3}` |
| `W-TRK001` | `strategy=3`（Grover）但缺少 ancilla 工作寄存器 → 降级为策略 0 |

### 7.3 既有标签修复

| 码 | 条件 |
| --- | --- |
| `E-TOP008` | `@layer` 出现未知键（**既有行为为静默丢弃，此处改为报错**） |
| `E-TOP009` | `@layer` 的 `time` / `thread` / `cost` / `deadline` 取负值 |

> `E-TOP008` 修复了一个既有隐患：`parseLayerTag` 的 `else if` 链没有 `else` 分支，
> 未知键（如拼错的 `thread2=1`）被静默丢弃。新机制引入更多键后，
> 这个静默失败会变成真实的用户困惑来源。

> `E-TOP009` 的存在理由是一条因果链：新机制需要 `shuttle_strategy=-1`
> （**本文档规定的默认值**）、`shuttle_lambda=-1`（须报 `E-SHU003`）这类负值，
> 而词法层把负号独立成 `Minus` token，旧的 `parseLayerTag` 一律 `eat(Number)` ——
> 于是负号会抛出**无错误码的 `Parser Error` 崩溃**。
> 解析层因此统一接受有符号数值，语义层再用 `E-TOP009` 拒绝无语义的负数
> （`time=-1` 会让分层排序失真，`cost=-1` 会让功能周期 `[time, time+cost]` 反向）。
>
> 把「语法上可写」与「语义上合法」分开，才能给出**带错误码的诊断**
> 而不是一个无码异常。同理，`dual=true` 也从崩溃改为可解析（`true`=1 / `false`=0）。
>
> `coord` 允许负数：coord 是格点**地址**而非计数，L1 距离对负地址同样良定义。
> 相应地，轮次跨度取 `∏ᵢ(coord_max[i] − min(0, coord_min[i]) + 1)`
> ——若沿用 `coord_max[i]+1`，全负地址会得到 `span=1` → `rounds=0`，
> 穿梭**静默地一轮都不做**。

### 7.4 运行期不变量

| 不变量 | 保障 | 实现位置 |
| --- | --- | --- |
| 影子槽绝不为 `QObject` 类型 | `static_assert` 要求平凡可复制 / 标准布局 / 非多态 | `ShuttleRuntime.hpp` |
| `w > 0` 无截断 | 编译期校验 `λ > 0`；运行期不设阈值；下溢对端按 `logWeight` 仍被调度 | `Ta.hpp`+`ShuttleRuntime.hpp` |
| L0 只用于 Pauli 族 | 非 Pauli 族不存在非破坏读出电路 → 作用域判定失效 | `ShuttleRuntime::scope_exit` |
| L1 必须有采样数 | 无采样即无法构成经典阴影 → 作用域判定失效 | `ShuttleRuntime::scope_exit` |
| `RESTORE` 后保真度 ≥ 门限 | L0/L2 门限 = 1；L1 门限 = 采样收敛下界；逐态校验由块经 `qstate_fidelity` 完成 | `TrackingPlanner::fidelity_contract` |
| 穿梭不复制量子态 | 载荷是经典关联标量；量子路径仅用受控 SWAP（移动）或扩散（混合） | `ShuttleRuntime`（载荷类型为 `double`） |
| 影子作用域不外泄 | 影子槽为块栈帧局部，作用域退出即 `erase` | `ShuttleRuntime::scope_exit` |
| 降级 / 跳过不静默 | W-SHU001 / W-TRK001 / 退化路径 / 失效作用域均写入诊断 | `ShuttleRuntime`（`ShuttleRuntimeStats`） |

> 上述不变量由 `runtime/tests/shuttle_tracking_runtime.cpp` 守护：该测试直接对
> **编译器真实产出的调度表**（而非手写 JSON）运行，从而同时覆盖「序列化格式漂移」
> 与「运行期语义漂移」两类静默缺陷。

## 8. 调度表线格式

`@rvdl_topology_json` 新增两个顶层段：

```json
{
  "shape":    { "time": 3, "thread": 2, "coord": [2, 1] },
  "blocks":   [ { "name": "f", "time": 1, "thread": 0, "coord": [0,0],
                  "cost": 1, "deadline": null } ],
  "callGraph":[ { "caller": "p", "callee": "c", "startAt": 2, "deltaT": 2 } ],

  "shuttleLinks": [
    { "from": "f", "targets": [ { "name": "g", "coord": [1,0],
                                  "logWeight": -1.0, "weight": 0.3679,
                                  "distance": 1, "via": "parallel" } ],
      "lambda": 0.5, "phase": 2, "rounds": 1, "strategy": -1,
      "slotsPerPhase": [ 1, 1 ] }
  ],

  "trackingScopes": [
    { "block": "sense", "observables": ["expect_z","measure_x","entropy"],
      "mode": 0, "slots": 2,
      "level": [0, 0, 1] }
  ]
}
```

- `targets` 按块名排序，与 `weight` / `logWeight` / `distance` / `via` 一一对应，保证确定性。
- `level` 与 `observables` 一一对应，记录 auto 模式**实际选中的级别**（供运行期与诊断核对）。
- 旧的调度表（无这两段）**继续有效**——运行期见到缺段即视为「无穿梭 / 无追踪」。

### `logWeight` 与 `weight` 必须同时下发

关联度有两种表示，缺一不可：

| 字段 | 定义 | 用途 | 数值性质 |
| --- | --- | --- | --- |
| `logWeight` | `-d_L1 / λ` | 运行期**路由 / 排序 / 可达性判定** | 任意有限距离均有限 |
| `weight` | `exp(logWeight)` | **线性混合** | `d/λ > 745.13` 时双精度**整零**（`d/λ ≳ 746`） |

> 整零阈值 `745.13` 是 `exp(−x)` 在双精度下真正变成 0 的那一点（次正规数也保不住），
> 由二分夹逼实测得出；`ln(DBL_MAX) ≈ 709.78` 是**正规数**下界，不是整零点。
> 两者相差 35 —— 拿后者当截断阈值会给出错误的「下溢」判断。

只下发 `weight` 会让「极远对端（关联低于机器精度）」与「被阈值截断」变得**不可区分**——
而这正是本设计要根除的现象。因此运行期**一律用 `logWeight` 决策**：
`d/λ = 999` 的对端仍被调度、仍参与排序，只是线性混合贡献为数值零。
这与注意力 softmax 把小权重直接归零有本质区别。

> 该性质由 `runtime/tests/shuttle_topology_parity.cpp` 的 [5] 组断言守护，
> 并由 `runtime/benchmarks/shuttle_plan_benchmark.cpp` 的 [3] 组复算（含整零阈值二分）。

> **MIR 路径必须同步**：`MirModuleBuilder.hpp` 的 `emitTopologyEntry` 目前会构造一个
> **缩减版**表（只有 `name/time/thread`，`coord` 硬编码为 `[1]`）。
> 若不同步更新，`--mir` 路径会**静默丢失**全部穿梭/追踪信息。
> 这是本次实施中最高优先级的对齐点。

## 9. 与既有机制的正交性

| 维度 | 既有 `@layer` | 穿梭 | 追踪 |
| --- | --- | --- | --- |
| 关心 | 块**在哪**（几何位置） | 数据**怎么到**关联块（流） | 数据**怎么留**（非破坏快照） |
| 依赖 | — | 五类关联边 | 可观测量族 |
| 作用域 | 全程序拓扑 | 穿梭群内关联块 | 单块功能周期 |
| 类型 | 无 | 权重为经典标量 | 影子槽为经典标量（**非 `QObject`**） |
| 诊断族 | `E-TOP001`–`E-TOP008` | `E-SHU001`–`E-SHU008` / `W-SHU001` | `E-TRK001`–`E-TRK004` / `W-TRK001` |

三者在语义上**完全正交**：`@layer` 定几何、穿梭定流、追踪定快照。
任何新键缺省时，既有行为逐字节不变。
